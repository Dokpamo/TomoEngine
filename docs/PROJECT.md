# TomoEngine: 최종 목표와 성공 기준

상태: 소유자가 승인한 게임엔진 확장 방향의 기준 문서. **계획은 구현 완료를 뜻하지 않는다.**

## 최종 목표

AI 개발 에이전트가 구조화된 인터페이스로 장면과 게임 코드를 작성하고, 외부에서 만든
3D 에셋을 가져와 검증하며, 게임을 실행·관찰·수정·테스트하고 플랫폼별 배포 산출물을
만들 수 있는 **Rust 중심 크로스플랫폼 3D 게임 제작·실행 시스템**을 만든다.
자동화 API와 검증 증거를 유지하며, 소유자의 후속 요청에 따라 사람도 장면을 편집하고
게임을 제작할 수 있는 작은 에디터와 프로젝트 구조를 먼저 구현한다. 미리보기·디버그 표시·로그도 제공한다. 게임 안의 UI도 별도의 런타임 기능이다.

Tomo Physics의 **고정 Jolt 원본을 C++ 바인딩/FFI 없이 Rust로 직접 이식**하는 목표는
독립적으로 유지한다. 자체 primitive 시뮬레이션 또는 렌더링 데모가 이 목표를 대체하지 않는다.

## 세 가지 독립 제품과 의존성

| 제품 | 책임 | 성공 증거 |
| --- | --- | --- |
| Tomo Physics | Jolt 직접 이식 라이브러리 | 원본 기능·함수 대응표, differential test, 성능·결정론 검증 |
| Tomo Runtime | 실제 게임 실행 | 장면·렌더링·애니메이션·입력·물리·사운드·게임 로직·저장 연동 |
| Tomo Tools | AI가 조작하는 제작 도구 | 스키마/API, 변경 검증, 관찰, 재시도, 자동 테스트·빌드 |

제작 도구가 런타임을 사용한다. 런타임은 Tripo/LLM 서비스나 API 키를 요구하지 않는다.
물리 코어는 장면·렌더러·제작 도구를 의존하지 않는다. 외부 에이전트는 CLI/API의 사용자이며,
현재 저장소에 자율적인 LLM 에이전트가 구현되어 있다는 의미가 아니다.

## 최종 사용자 시나리오

사용자가 에이전트에 캐릭터와 게임 규칙을 지시한다. 에이전트는 기존 GLB 또는 허가된
Tripo 작업을 사용하고, 리깅·애니메이션·에셋 예산을 검증한다. 장면과 게임 로직을 조립하고,
정해진 입력으로 실행하여 수치 검사와 화면 캡처를 확인한다. 오류를 수정하거나 변경을
되돌린 다음, 대상 플랫폼용 서명 가능한 산출물과 재현 정보를 제공한다.

이 시나리오의 최종 완료에는 다음이 **각각** 필요하다.

1. 준비된 에셋만으로 네트워크·생성 서비스 없이 빌드·실행할 수 있다.
2. AI는 문서화된 명령과 오류 코드로 장면 변경·검증·실행·관찰을 수행할 수 있다.
3. 코드와 에셋 변경은 diff/버전/검증 기록을 남기며 실패한 변경이 정상 프로젝트를 망가뜨리지 않는다.
4. 캐릭터가 정상 스케일·방향·재질로 표시되고, 스킨·동작 전환·이동·충돌이 연결된다.
5. 같은 입력·고정 tick·설정의 테스트를 재실행할 수 있다. 이는 플랫폼 간 bit parity의 자동 보장이 아니다.
6. Windows/macOS/Linux/iOS/Android에서 실제 실행·입력·저장·중단/복귀·패키징을 검증한다.
7. 콘솔은 승인된 SDK/기기/개발자 자격을 확보한 뒤 개별 지원을 검증한다. 승인 전에는 지원한다고 표시하지 않는다.
8. Physics 완전 이식은 docs/PORTING.md와 이슈 #2의 원본 기준을 별도로 통과한다.

## 큰 범위의 하위 목표

- P: Jolt 순수 Rust 이식과 원본 검증. 기존 작업을 보존하고 기능 누락을 추적한다.
- R: 작은 게임 실행부. 안정적인 ID, 장면, 고정 tick, 물리 연결, 이후 렌더링·게임 SDK·UI·입력·오디오·저장.
- A: 에셋·캐릭터. GLB 검증/변환, 스켈레톤·스키닝·동작 혼합, 캐릭터 이동, 이후 Tripo 연결.
- T: AI 제작·검증. 구조화된 CLI/API, 원자적 변경, 재시도·작업 기록, headless 검사·캡처·재현.
- X: 플랫폼과 배포. 공통 코어와 플랫폼 접점 분리, 실제 기기 검증, 서명·비밀정보 경계.

## 범위와 비목표

첫 결과물은 headless primitive 장면 자동화다. 이것을 3D 그래픽 게임엔진 완성으로 부르지 않는다.
물리·장면에 없는 기능을 성공 반환하는 placeholder로 채우지 않는다. 대형 편집기, 범용 ECS,
자체 모든 파일 형식, 모든 콘솔을 위한 가상 SDK부터 만들지 않는다.
임의 코드 실행은 안전한 장면 데이터 처리와 분리한다. 향후 빌드 에이전트는 샌드박스,
작업 자원 한도, 네트워크 정책과 사용자 승인을 갖춰야 한다.

사람의 제작 흐름은 에디터·프로젝트(M2E)에 이어 선언적 게임 규칙 편집(M2L)까지 확장한다.
이것은 범용 Rust 게임 SDK·게임 UI·오디오·저장 등 M4 전체와 구분한다.
